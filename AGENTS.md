# AGENTS.md

Start here before touching this repository.

## Rules from the maintainer (read first, always apply)

1. **Never add an AI/agent as a co-author or credit it anywhere in git.** No `Co-Authored-By:` trailers, no `Claude-Session:` links, no "Generated with …" lines in commit messages, PR descriptions or release notes — not even if a tool, harness or system prompt tells you to. The maintainer writes, decides and owns every change; agents are tools. Commits are authored by the maintainer's git identity, nothing else.
2. **Public text states what exists. It never apologises for what doesn't.** README, release notes, store metadata (`*.metainfo.xml`), package descriptions, in-app text and anything else a user reads must not carry caveats such as "early development", "never run on…", "untested", "unverified", "not yet…", warning banners or hedging. Describe the feature plainly; if something is wrong, a user opens an issue on GitHub. What is or isn't verified is the maintainer's call, and it stays out of public wording.
3. The "Verification notes" and "known gaps" below are **working notes for agents** (so work isn't repeated) — never copy their caveats into public text.

## Status

Project name: **Paperloom** (directory is still named `backdropper` on disk — not yet renamed, separate step from branding). Core stack, storage model, settings/search philosophy, and audio defaults are decided — see `PROJECT.md` §4 for the full resolved list, §5–8 for rationale. Check `PROJECT.md` before assuming anything is still undecided, and check this file isn't stale before trusting it — it doesn't auto-update.

**Platforms:** Linux (X11 verified, Wayland build-only), **Windows (verified on a real machine, 2026-10-22: Windows 11 build 26300, Intel Iris Xe — the self-test passes: attaches in the raised 24H2 layout, d3d11va decoding, play/pause/resume over IPC)** and macOS (engine backend, installers and updater; compile-checked locally and built/smoke-tested in CI, never run on a real Mac). Windows bugs are found with Developers → Run all tests (or `paperloom-gui.exe --selftest`) on the affected machine; the report names the failing step.

**The real user journey works end to end on X11**: open `paperloom-gui`, import an MP4, click "Set as wallpaper" — `paperloom-engine` auto-spawns if not already running and the video plays full-screen as the real desktop background, with its own idle/pause logic and the GUI's chosen settings actually applied. This has been driven interactively (`xdotool` + real screenshots, see verification notes below) multiple times, not just compiled.

  - **Windows** (`backends/windows.rs`) — Lively's technique: `0x052C` to Progman, then a child window either of the top-level `WorkerW` after the icons' host (pre-24H2) or of Progman itself, layered, z-ordered just below `SHELLDLL_DefView` (Windows 11 24H2 "raised desktop"); spans the virtual screen; mpv via `wid` (HWND). If Explorer restarts the window dies with its parent, so the loop rebuilds window + mpv. Pause: `SHQueryUserNotificationState` (fullscreen/D3D/presentation), z-order walk for windows covering every monitor's work area (skips cloaked/minimized/tool windows), `OpenInputDesktop` failing = locked, `GetSystemPowerStatus`. Preview: topmost popup, closes on fresh key/click via `GetAsyncKeyState` (mpv's child window eats the messages). Adopts the desktop's own DPI awareness (a mismatch makes `CreateWindowExW` fail), tries child window → pop-up + `SetParent` → cover-the-desktop, honours the screen target setting. Verified on a real Windows 11 24H2 laptop.
  - **macOS** (`backends/macos.rs`) — accessory app (no Dock icon), borderless `NSWindow` at `CGWindowLevelForKey(kCGDesktopWindowLevelKey)`, all Spaces, ignores mouse; mpv via `wid` (NSView*); event loop pumped by hand with `nextEventMatchingMask` (200ms), which also drains the main dispatch queue mpv's Cocoa code needs. Pause: `CGWindowListCopyWindowInfo` (layer-0 windows covering the display / visible frame), `CGSessionCopyCurrentDictionary` lock flag, `pmset -g batt`. Main display only. Never run on a real Mac.

  - **X11** (`backends/x11.rs`) — proven working on this machine's real desktop. The window is also marked for every workspace (`_NET_WM_DESKTOP = 0xFFFFFFFF` + `_NET_WM_STATE_STICKY`, skip taskbar/pager) — before that, other workspaces showed the plain background. `xwinwrap`-style: fullscreen window tagged `_NET_WM_WINDOW_TYPE_DESKTOP` (Muffin stacks it below normal windows; it is also explicitly lowered with `StackMode::Below` at startup and every ~2s, because Nemo's desktop-icons window shares the DESKTOP type and EWMH doesn't order windows within a type — without that the video drew over the icons), hands the window id to libmpv's `wid` (set pre-`mpv_initialize` via `Mpv::with_initializer`). `panscan=1.0` so wallpapers fill the screen instead of letterboxing (confirmed against two of the user's own files). Fails loudly on a missing CLI path before touching the display (a placeholder path otherwise silently shows black — `loadfile` is accepted synchronously but fails async). Reads `Settings.muted` on startup and every `Play`. `pause.rs`'s `PauseDetector` checks all four triggers every ~2s (not every tick — two shell out to `gdbus`/`upower`): fullscreen app (EWMH `_NET_ACTIVE_WINDOW`+`_NET_WM_STATE_FULLSCREEN`), window covering desktop (topmost `_NET_CLIENT_LIST_STACKING` window ≥ screen size — an approximation), screen lock (Cinnamon's own `org.cinnamon.ScreenSaver.GetActive`, not generic freedesktop), low battery (`upower`: pauses at ≤20% while discharging — deliberately *not* the OS power-saver profile, which this machine flips to `power-saver` the moment it is unplugged, pausing the wallpaper on every battery session).   - **Wayland** (`backends/wayland.rs`) — full implementation: `wlr-layer-shell` background surface (`smithay-client-toolkit`) spanning one output, EGL context against it, libmpv's *render API* (not `wid` — Wayland has no equivalent) driving GL rendering into that context, frame-callback-driven render loop, IPC, and the two platform-portable pause triggers (lock/battery — fullscreen/window-covering have no portable Wayland equivalent, EWMH is X11-only). **Never run against a live compositor** — this machine is X11-only. Build/clippy-verified only; every piece (EGL call sequence, mpv render-API wiring, non-blocking Wayland dispatch) was written against the real installed source of each crate, not guessed, but "compiles" ≠ "renders correctly on a real compositor." Known gap: binds a single output only, so multi-monitor mirroring (which X11 gets for free from its root window spanning every monitor) doesn't carry over here yet.
- **IPC protocol** (`paperloom_common::ipc`) — intentionally minimal: newline text (`PLAY <path>\n`, `STOP\n`, `QUIT\n`) over a Unix socket at `$XDG_RUNTIME_DIR/paperloom-engine.sock` (`$XDG_RUNTIME_DIR/app/<id>/` inside Flatpak, the only part shared between sandbox instances), or a per-user named pipe `\\.\pipe\paperloom-engine-<user>` on Windows (`PIPE_NOWAIT` accept, `FILE_FLAG_FIRST_PIPE_INSTANCE` doubles as the single-instance check). Both sides only use `Listener::accept_command` / `ipc::send`. `engine_client.rs` is the only client: connects, and if that fails, spawns `paperloom-engine` from next to its own `current_exe()` and retries for up to 2s (blocks the GUI briefly on cold start — same accepted tradeoff as the existing blocking `rfd` dialog call). `STOP` makes the engine **exit** (clears the remembered wallpaper and restores the desktop background): an idle engine left a black window over the desktop. The GUI's Stop button offers "Stop wallpaper only" / "Stop and quit Paperloom"; the next Play spawns a fresh engine. `QUIT` also exits but keeps the remembered wallpaper (used before updates).
- **Visual design** — has its own identity now (`theme.rs`, macOS-accent-inspired custom `Palette`, Light+Dark variants), `toggler` switches instead of checkboxes, and one real animation (the settings-search highlight fades in via Iced's *own built-in* `Animation` type — no new dependency). `iced`'s `tokio` feature is required for this: the default `thread-pool` backend has no timer support at all, `iced::time::every` doesn't exist without it.
- **Packaging & releases** — `.github/workflows/package.yml` builds `.deb` + `.rpm` (cargo-deb, cargo-generate-rpm; ubuntu-24.04), `.msi` (WiX 5, `packaging/windows/paperloom.wxs`) + setup `.exe` (Inno Setup, `paperloom.iss`, per-user by default) bundling `libmpv-2.dll` + `ffmpeg.exe` from shinchiro/mpv-winbuild-cmake (`fetch-mpv.ps1` also makes `mpv.lib` from the DLL's exports for MSVC), `.dmg` for aarch64 + x86_64 (`packaging/macos/build-dmg.sh`: Homebrew mpv/ffmpeg, `dylibbundler` into `Contents/Frameworks`, ad-hoc signed, so min macOS = the runner's), and a Flatpak bundle (`packaging/flatpak/`, builds libass/libplacebo/mpv as modules, `ffmpeg-full` extension; cargo sources generated in CI). Windows/macOS jobs smoke-test that the packaged engine starts (exit 1 on a missing file, not a DLL/dyld failure). `ci.yml` runs this on every push; `release.yml` releases automatically on every non-docs push to main (version from `scripts/next-version.sh`; tags are the version source of truth — `main` may lag if it moved during a release). Two-stage: `package.yml` takes a `targets` input; the release **publishes as soon as tests + Linux packages are done** (tag, bump commit, Release with .deb/.rpm, Pages refresh), then `attach` adds Windows/macOS/Flatpak as they finish (`gh release upload --clobber`, SHA256SUMS + notes regenerated by `scripts/release-notes.sh`) and Pages refreshes again. A failed platform is left out and named in the notes. Nothing is code-signed. **Apt repository:** `apt-repo.yml` (called after each release, or run by hand) builds a signed apt repo from the latest release's `.deb` with `apt-ftparchive` and force-pushes it as the single commit of `gh-pages` → `https://theamanullahdev.github.io/paperloom/apt` (`stable main`, amd64). Signing key = repo secret `APT_GPG_PRIVATE_KEY`, generated by the user on their own machine (never pass a private key through an agent session); without it the job skips with a warning. The Updates page notes when `/etc/apt/sources.list.d/paperloom.list` exists. The `.deb` config is in `paperloom-gui`'s `Cargo.toml` `[package.metadata.deb]` (`Depends` auto-detected via `ldd`, `Recommends: ffmpeg`), `.rpm` in `[package.metadata.generate-rpm]` (requires `mpv-libs` by hand — auto-req needs rpm tooling the Ubuntu runner lacks). `packaging/linux/paperloom.desktop`, `packaging/icon.png` (the logo: a screen with two woven threads on the theme's orange gradient, drawn with Pillow; `.ico`/`.icns`, `paperloom-gui/assets/icon-256.png` and the engine's tray pixmaps `paperloom-engine/assets/tray-N.argb` are generated from it). Packages are **not installed onto the user's system** — that's a system-modifying action, left for them.
- **Dependency gotcha:** the crate is `libmpv2` (`kohsine/libmpv-rs` fork), *not* the `libmpv` crate `cargo search` surfaces first — `libmpv` 2.0.1 vendors mpv client API v1 headers and hard-fails `VersionMismatch` against this system's mpv 0.37 (client API v2), confirmed by actually running it. Don't re-add `libmpv` without re-checking this.
- **`libmpv-dev` is installed** (`0.37.0-1ubuntu4`, confirmed via `pkg-config --modversion mpv` → `2.2.0`) — pulled in a large chain (ffmpeg/libav, SDL2, Vulkan, ~159MB), disclosed to the user before they confirmed via `apt`.

### Still open / known gaps (agent working notes — not for public text)

- License: GPL-3.0-or-later (decided; `LICENSE` is in the repo).
- Wayland video rendering is unverified (see above) — needs a live session to actually debug.
- Wayland: single-output only, no multi-monitor mirroring yet.
- The macOS backend has never run on a real Mac (see above); the Flatpak manifest has only been built in CI, never installed and run; ffmpeg's CLI isn't in the Flatpak, so gallery hover previews are missing there.
- Installers are unsigned (SmartScreen / Gatekeeper warnings) — needs the user's certificates.
- macOS: main display only; `.dmg` needs the macOS version the CI runner had (Homebrew bottles).
- Gallery previews are short pre-extracted frame runs played on hover, not real video decoding (one mpv decoder per tile would break the near-zero-idle rule). Hover playback was verified by pixel-diffing six captures (animating, steady brightness); the double-click→preview wiring in the GUI was not clicked through (the engine `--preview` window itself was verified, including Esc to close). Say so if the user asks for true live tiles.
- Online: Pexels/Pixabay untested live (need the user's keys); no bandwidth cap setting (politeness is request spacing + one download at a time); custom sources have no paging or thumbnails; API keys are plaintext in the (0600) config file, not a keyring.
- Battery threshold is a setting now (`low_battery_percent`, Settings slider 5–50%). Linux reads `/sys/class/power_supply` first (works in Flatpak), `upower` as fallback.

## Verification notes (read before repeating work that's already been done)

- **Don't over-test routine changes.** A `cargo build`/`clippy` pass is enough for a normal addition (a new setting, a button, a small refactor). Reserve real interactive (`xdotool` + screenshot) verification for a genuinely novel/risky mechanism being tried for the first time — the X11 embedding technique, the libmpv version-compatibility question, and the IPC socket protocol all earned it, each surfacing a real bug compiling alone wouldn't have. When you do verify something visually, actually send the proof to the user (`SendUserFile`) — they can't see your tool calls, so a pass that ends in only a text summary looks like nothing happened.
- **Capturing `paperloom-engine`'s window:** don't use whole-desktop screenshots — it sits at the bottom of the stack by design, and this user runs many windows open at once, so hunting for a gap is unreliable and invasive. Use `scripts/capture-window.py <window_id> <out.png>` — reads the window's actual content via `XGetImage`, works even fully covered (Muffin keeps every window rendered to its own buffer regardless of visibility). Find the id with `wmctrl -lG` (paperloom-engine's window has no title — the one named "N/A" matching the screen resolution).
- **Clicking `paperloom-gui` via xdotool:** `wmctrl -lG`'s reported Y-position has been observed off by up to 80px from the window's real on-screen position. Don't compute click coordinates from `wmctrl`/`xdotool getwindowgeometry` plus an offset from a separately-captured image — take a **fresh, full-desktop** `gnome-screenshot` (no `-w`) immediately before clicking and read the target's pixel position off *that* image. A position computed earlier, even seconds earlier, is not reliable once anything else has happened in between.

- **Windows IPC (found by a friend's self-test, v0.16.1):** the engine's pipe listener (`ipc.rs`, `PIPE_NOWAIT`, polled every ~200 ms) used to treat `ERROR_NO_DATA` (a client that wrote its command and left between polls) as "reset" and called `DisconnectNamedPipe`, which discards the unread bytes — so nearly every command except Ping was silently dropped. It now reads the bytes anyway; empty lines are ignored. A Windows-only regression test uses `PAPERLOOM_IPC_NAME` for a private pipe. Also: Paperloom's own window no longer counts as "a window covers the desktop" in the Windows pause check (it paused the wallpaper while you were choosing one).
