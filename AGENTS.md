## Status

Project name: **Paperloom** (directory is still named `backdropper` on disk — not yet renamed, separate step from branding). Core stack, storage model, settings/search philosophy, and audio defaults are decided — see `PROJECT.md` §4 for the full resolved list, §5–8 for rationale. Check `PROJECT.md` before assuming anything is still undecided, and check this file isn't stale before trusting it — it doesn't auto-update.

**The real user journey works end to end on X11**: open `paperloom-gui`, import an MP4, click "Set as wallpaper" — `paperloom-engine` auto-spawns if not already running and the video plays full-screen as the real desktop background, with its own idle/pause logic and the GUI's chosen settings actually applied. This has been driven interactively (`xdotool` + real screenshots, see verification notes below) multiple times, not just compiled.

### Crates

- **`paperloom-common`** — shared, dependency-light (`paperloom-engine` must never drag in GUI deps). `Settings` (schema + TOML at `paths::config_file()`), `Library` (import manifest at `library_dir()/library.toml` — needed because `ImportMode::ReferenceInPlace` entries aren't inside that folder; each entry carries 3s of consecutive `ffmpeg`-extracted `preview_frames` (10fps, 320px, one ffmpeg run; `preview_version` triggers a one-time regeneration when the scheme changes) for the gallery's hover preview, and an optional `source_id` for wallpapers that came from the online library), `display::primary_aspect_ratio` (parses `xrandr`; the gallery's preview area uses the real screen ratio), `ipc` (the GUI↔engine wire protocol — see below). Has unit tests (`cargo test -p paperloom-common`) against scratch temp dirs, never real XDG paths.
- **`paperloom-fetch`** — online library backend; only the GUI depends on it (keeps `ureq`/TLS out of the always-on engine). `source::Source` trait; built-in sources chosen by `SourceSetting::id`: `motionbgs::MotionBgs` (scrapes server-rendered HTML; `/dl/hd/<id>/` always, `/dl/4k/<id>/` when the tile is badged 4K; both serve the MP4 directly with Range support; only robots-allowed paths), `pexels::Pexels` and `pixabay::Pixabay` (JSON video APIs, free API key required, **parsing is unit-tested against sample JSON only — never run against the live APIs, no keys yet**), and `generic::PageSource` for user-added URLs (finds every `.mp4` link in a page/JSON response; `{q}` in the URL = search text; optional Bearer key; no paging). `aggregate::fetch_page` queries every enabled source in parallel, round-robins/de-dupes results, keeps per-source paging cursors, and returns per-source failure notices without failing the whole page; `net::is_online` (sysfs interface check + 3 parallel TCP probes to IP literals) makes "offline" instant. Items carry `variants` (HD / 4K) and the queue downloads the chosen one. `http.rs`: shared agent plus three throttle lanes (page 700ms, image 120ms, download 1.5s). `download.rs`: one resumable attempt — `.part` + HTTP `Range`, rejects non-MP4 bodies, 404/other-4xx permanent, 429/5xx/network transient. `queue.rs`: persistent, reorderable (`move_job`) queue, one worker; transient failures retry **forever** (5s→120s backoff), waits without burning attempts while offline, keeps its reference across restarts; only permanent failures stop (listed with Retry). Tests: unit tests (incl. local-server resume/drop tests), `tests/retry.rs`, and an `#[ignore]`d live test (`XDG_DATA_HOME=$(mktemp -d) XDG_CACHE_HOME=$(mktemp -d) cargo test -p paperloom-fetch --test live -- --ignored`). Unsplash is not supported (photos only; the engine plays video).
- **`paperloom-gui`** — Iced 0.14. `app.rs` (shell/nav, hands finished downloads to the library), `pages/library.rs` (gallery of cards: preview area at the real screen ratio — a still poster at rest, and only the hovered tile plays its frames ping-pong at 10fps; frames are explicitly GPU-`allocate`d first (iced draws un-allocated images a frame late, which was the black flicker), playback starts only when all are ready; double-click opens a full-screen preview via `paperloom-engine --preview <file>` (X11/XWayland, Esc/click/any key closes), bottom "Set as wallpaper" button, top-right kebab menu → Remove with confirm; multi-file import via `pick_files`), `pages/online.rs` (aggregated search, All/4K/HD filter, per-card Download HD / Download 4K, instant offline screen that auto-rechecks, "In your library" marker), `pages/downloads.rs` (every download with progress/speed/ETA/URL/destination/part path, drag-to-reorder + "Top"; reached from the always-visible top-right download button), `pages/sources.rs` (enable/disable sources, API keys, add custom URL sources; stored in `Settings::sources`, config file is chmod 600), `pages/gallery.rs` (shared grid sizing), `pages/settings/`, `engine_client.rs` (IPC client), `theme.rs` (custom palette; `ThemeMode::System` follows `iced::system::theme()`). Icons are vendored Lucide (ISC). Verified interactively: settings/library flows earlier; this session the Online tab end to end (live listing → thumbnails → Download → `.part` growing → imported with title → card shows "In your library").
- **`paperloom-engine`** — the renderer/daemon, a real Unix-socket daemon on both backends (binds `paperloom_common::ipc::socket_path()`, non-blocking accept, optional CLI path arg for direct dev testing).
  - **X11** (`backends/x11.rs`) — proven working on this machine's real desktop. `xwinwrap`-style: fullscreen window tagged `_NET_WM_WINDOW_TYPE_DESKTOP` (Muffin stacks it below normal windows; it is also explicitly lowered with `StackMode::Below` at startup and every ~2s, because Nemo's desktop-icons window shares the DESKTOP type and EWMH doesn't order windows within a type — without that the video drew over the icons), hands the window id to libmpv's `wid` (set pre-`mpv_initialize` via `Mpv::with_initializer`). `panscan=1.0` so wallpapers fill the screen instead of letterboxing (confirmed against two of the user's own files). Fails loudly on a missing CLI path before touching the display (a placeholder path otherwise silently shows black — `loadfile` is accepted synchronously but fails async). Reads `Settings.muted` on startup and every `Play`. `pause.rs`'s `PauseDetector` checks all four triggers every ~2s (not every tick — two shell out to `gdbus`/`upower`): fullscreen app (EWMH `_NET_ACTIVE_WINDOW`+`_NET_WM_STATE_FULLSCREEN`), window covering desktop (topmost `_NET_CLIENT_LIST_STACKING` window ≥ screen size — an approximation), screen lock (Cinnamon's own `org.cinnamon.ScreenSaver.GetActive`, not generic freedesktop), low battery (`upower`: pauses at ≤20% while discharging — deliberately *not* the OS power-saver profile, which this machine flips to `power-saver` the moment it is unplugged, pausing the wallpaper on every battery session). Each degrades to `false` if unavailable, never errors.
  - **Wayland** (`backends/wayland.rs`) — full implementation: `wlr-layer-shell` background surface (`smithay-client-toolkit`) spanning one output, EGL context against it, libmpv's *render API* (not `wid` — Wayland has no equivalent) driving GL rendering into that context, frame-callback-driven render loop, IPC, and the two platform-portable pause triggers (lock/battery — fullscreen/window-covering have no portable Wayland equivalent, EWMH is X11-only). **Never run against a live compositor** — this machine is X11-only. Build/clippy-verified only; every piece (EGL call sequence, mpv render-API wiring, non-blocking Wayland dispatch) was written against the real installed source of each crate, not guessed, but "compiles" ≠ "renders correctly on a real compositor." Known gap: binds a single output only, so multi-monitor mirroring (which X11 gets for free from its root window spanning every monitor) doesn't carry over here yet.
- **IPC protocol** (`paperloom_common::ipc`) — intentionally minimal: newline text (`PLAY <path>\n`, `STOP\n`) over a Unix socket at `$XDG_RUNTIME_DIR/paperloom-engine.sock`. `engine_client.rs` is the only client: connects, and if that fails, spawns `paperloom-engine` from next to its own `current_exe()` and retries for up to 2s (blocks the GUI briefly on cold start — same accepted tradeoff as the existing blocking `rfd` dialog call). `Stop` exists end-to-end (engine handles it, GUI's "Stop wallpaper" button sends it).
- **Visual design** — has its own identity now (`theme.rs`, macOS-accent-inspired custom `Palette`, Light+Dark variants), `toggler` switches instead of checkboxes, and one real animation (the settings-search highlight fades in via Iced's *own built-in* `Animation` type — no new dependency). `iced`'s `tokio` feature is required for this: the default `thread-pool` backend has no timer support at all, `iced::time::every` doesn't exist without it.
- **Packaging** — `.deb`, via `cargo-deb` (already installed on this machine), config in `paperloom-gui`'s `Cargo.toml` `[package.metadata.deb]`. Built and verified for real: `cargo deb -p paperloom-gui` → `target/debian/paperloom_<ver>_amd64.deb`, checked with `dpkg -c`/`dpkg -I` (both binaries + desktop file + icon present, `Depends: libc6, libmpv2` correctly auto-detected via `ldd` against the actual compiled binary — not hand-maintained). `packaging/paperloom.desktop` + `packaging/icon.png` (a generated placeholder, not real branding). **Not installed onto the user's system** — that's a system-modifying action, left for them. No Flatpak manifest: needs the full Cargo dependency tree vendored offline (`flatpak-cargo-generator`), real separate work; `.deb` was what's actually achievable and fully verifiable here.
- **Dependency gotcha:** the crate is `libmpv2` (`kohsine/libmpv-rs` fork), *not* the `libmpv` crate `cargo search` surfaces first — `libmpv` 2.0.1 vendors mpv client API v1 headers and hard-fails `VersionMismatch` against this system's mpv 0.37 (client API v2), confirmed by actually running it. Don't re-add `libmpv` without re-checking this.
- **`libmpv-dev` is installed** (`0.37.0-1ubuntu4`, confirmed via `pkg-config --modversion mpv` → `2.2.0`) — pulled in a large chain (ffmpeg/libav, SDL2, Vulkan, ~159MB), disclosed to the user before they confirmed via `apt`.

### Still open / known gaps

- License: GPL-3.0-or-later (decided; `LICENSE` is in the repo).
- Wayland video rendering is unverified (see above) — needs a live session to actually debug.
- Wayland: single-output only, no multi-monitor mirroring yet.
- No Flatpak manifest yet (see Packaging above).
- Gallery previews are short pre-extracted frame runs played on hover, not real video decoding (one mpv decoder per tile would break the near-zero-idle rule). Hover playback was verified by pixel-diffing six captures (animating, steady brightness); the double-click→preview wiring in the GUI was not clicked through (the engine `--preview` window itself was verified, including Esc to close). Say so if the user asks for true live tiles.
- Online: Pexels/Pixabay untested live (need the user's keys); no bandwidth cap setting (politeness is request spacing + one download at a time); custom sources have no paging or thumbnails; API keys are plaintext in the (0600) config file, not a keyring.
- Battery threshold (20%) is a constant in `pause.rs`, not a setting yet.

## Verification notes (read before repeating work that's already been done)

- **Don't over-test routine changes.** A `cargo build`/`clippy` pass is enough for a normal addition (a new setting, a button, a small refactor). Reserve real interactive (`xdotool` + screenshot) verification for a genuinely novel/risky mechanism being tried for the first time — the X11 embedding technique, the libmpv version-compatibility question, and the IPC socket protocol all earned it, each surfacing a real bug compiling alone wouldn't have. When you do verify something visually, actually send the proof to the user (`SendUserFile`) — they can't see your tool calls, so a pass that ends in only a text summary looks like nothing happened.
- **Capturing `paperloom-engine`'s window:** don't use whole-desktop screenshots — it sits at the bottom of the stack by design, and this user runs many windows open at once, so hunting for a gap is unreliable and invasive. Use `scripts/capture-window.py <window_id> <out.png>` — reads the window's actual content via `XGetImage`, works even fully covered (Muffin keeps every window rendered to its own buffer regardless of visibility). Find the id with `wmctrl -lG` (paperloom-engine's window has no title — the one named "N/A" matching the screen resolution).
- **Clicking `paperloom-gui` via xdotool:** `wmctrl -lG`'s reported Y-position has been observed off by up to 80px from the window's real on-screen position. Don't compute click coordinates from `wmctrl`/`xdotool getwindowgeometry` plus an offset from a separately-captured image — take a **fresh, full-desktop** `gnome-screenshot` (no `-w`) immediately before clicking and read the target's pixel position off *that* image. A position computed earlier, even seconds earlier, is not reliable once anything else has happened in between.

## Ground rules for any agent working here
- **Never use interactive popup question tools with this user** (e.g. AskUserQuestion). They dictate prompts via voice notes and can't click popup options. Ask clarifying questions as plain chat text instead: question, then its options, then the next question, then its options, etc. — so they can answer everything in one dictated reply.
- Ask before assuming. If `PROJECT.md` marks something `TBD` or has it under "Open questions", don't decide it unilaterally — surface it to the user. (License is the live example right now.)
- Performance is a hard requirement, not an aspiration: the shipped app must use effectively zero CPU/RAM when idle (no wallpaper visible, locked screen, fullscreen app on top, etc.). Weigh every architectural choice against this.
- GUI-only. No CLI-first design, no CLI-only configuration path.
- Target platform is Linux (Ubuntu / Linux Mint), primary DE is Cinnamon.
- Intended to eventually be public (GitHub) and distributed via Flatpak (see Packaging above for current state).
